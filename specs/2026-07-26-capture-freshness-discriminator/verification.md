## Cold-review disposition

A cross-provider Claude review blocked the first pass. The actionable findings
were fixed:

- durable capture-write failure is now a tracked failure, not a completion;
- concurrent receipt ordering cannot clear a newer or late-finishing failure;
- already-in-flight success cannot clear a failure that finishes after it
  started;
- both Baileys listeners contain errors, and unresolved failure evidence
  survives tracker reconstruction through an atomic mode-0600 sidecar;
- inbox divergence uses the first unmatched capture's `capturedAt`, so
  continuing arrivals cannot hide a stopped inbox;
- missing markers, subsidiary reads, queue telemetry, and malformed config all
  fail with their own named conditions;
- final alert output no longer contains message IDs.

The review's request to red on row age beyond the measured baseline was
rejected: it recreates the exact quiet-versus-stopped ambiguity this WB removes.
An arrival that starts but does not finish is the red discriminator; a period
with no inbound receipts remains quiet, with row age and measured-baseline
position reported as context.

After the fixes, the same cross-provider reviewer returned `CLEAR` on the
durable-write contract, listener containment, concurrency ordering, persisted
restart snapshot, and consumer classification.

Deployment preconditions for the later Teren-authorized change:

- confirm `WHATSAPP_CAPTURE_EVENTS_PATH` is set and writable before starting
  the new bridge (it is the source for both durable capture and the failure
  sidecar);
- deploy the bridge producer before refreshing the canonical check-runner
  checkout;
- treat a malformed persisted sidecar as a fail-closed bridge-start error, not
  a file to delete without inspecting.
